# 太空猎人 - GPU 能力开发任务书

## 一、背景

当前「通道 A（保真增强）」已完成 P0 升级，基于 astropy 传统算法链路：
**Background2D 去背景 → astroscrappy 宇宙线去除 → ZScale + AsinhStretch 拉伸**。

用户提出的深度学习增强需求（noise2void / DIP / 超分 / deepCR），由于目前服务器无 GPU，暂不开发。
本任务书定义 GPU 到位后需要落地的全部 AI 增强能力，作为后续开发的统一规划。

---

## 二、目标

在配置独立 GPU 服务器后，为「太空猎人」双通道平台增加 4 项 AI 图像增强能力：

| 编号 | 能力 | 归属通道 | 技术路线 | 优先级 |
|------|------|----------|----------|--------|
| AI-1 | 自监督去噪 | 通道 A | Noise2Void (N2V) 在线自训练 | P1 |
| AI-2 | 深度学习宇宙线去除 | 通道 B 模式 | deepCR 预训练模型推理 | P3 |
| AI-3 | AI 超分辨率 | 通道 B 模式 | Swin2SR / AstroSR 微调 | P2 |
| AI-4 | 单图精细恢复 | 通道 B 模式 | DIP / DIPLI 无监督优化 | P4 |

---

## 三、各能力详细说明

### AI-1 Noise2Void 自监督去噪

**原理**：盲点网络自监督去噪，mask 掉中心像素用周围像素预测。无需干净图像对，单图即可训练。

**技术选型**：
- 框架：PyTorch
- 实现库：
2v（官方 N2V 实现，有 PyTorch 版本）或自实现 U-Net 结构
- 训练方式：用户上传单图 → 服务器端在线训练 100~200 epochs → 推理输出

**关键参数（前端可调）**：
- 训练步数 / epochs（默认 100 步）
- 去噪强度（通过训练步数间接控制）

**性能预期（GPU）**：
- 2K 图（2000×1500）：训练 100 步 ~ 30~60s，推理 < 1s
- 4K 图（4000×3000）：训练 100 步 ~ 2~4min，推理 ~ 2~3s

**集成位置**：通道 A 链路（去背景之后、拉伸之前），作为可选"AI 去噪"开关。

**开发工作量**：约 5~7 人天

---

### AI-2 deepCR 宇宙线去除

**原理**：基于 CNN 的宇宙线检测，在哈勃望远镜数据上训练。输出宇宙线 mask，再做修复。

**技术选型**：
- 官方库：deepcr（PyTorch）
- 模型选择：
  - ACS-WFC（哈勃高级巡天相机）
  - WFC3-UVIS（哈勃广角相机3）
  - DECam（暗能量相机）
- 待验证：民用天文摄影数据的泛化效果

**关键参数**：
- 模型选择（下拉菜单）
- 检测阈值（confidence）

**性能预期**：
- 2K 图推理：< 2s
- 4K 图推理：< 10s

**集成位置**：通道 B 的「宇宙线去除（AI版）」模式，与通道 A 的 astroscrappy 形成对比。

**开发工作量**：约 2~3 人天

---

### AI-3 超分辨率（Swin2SR / AstroSR）

**原理**：基于 Swin Transformer 的超分辨率网络，将图像 ×2 / ×4 放大同时恢复细节。

**技术选型**：
- 基线模型：Swin2SR（通用超分 SOTA，直接推理）
- 进阶方向：用 AstroSR 风格数据集（HSC/SDSS 星系配对）微调天文专用模型
- 倍率：×2、×4 可选

**关键参数**：
- 超分倍率（×2 / ×4）
- 模型选择（通用 / 天文专用）

**性能预期**：
- ×2 超分 2K → 4K：~ 3~5s
- ×4 超分 2K → 8K：~ 10~15s

**集成位置**：通道 B 的「AI 超分」模式。

**开发工作量**：
- 基线版（Swin2SR 预训练）：3~4 人天
- 天文微调版：额外 7~10 人天（含数据准备、训练）

---

### AI-4 DIP / DIPLI 单图精细恢复

**原理**：
- DIP（Deep Image Prior）：无监督，用随机噪声输入 + CNN 生成器迭代优化逼近输入图
- DIPLI（DIP + Lucky Imaging）：多帧幸运成像融合，效果显著优于单图 DIP

**技术选型**：
- 框架：PyTorch
- 网络结构：U-Net 或 skip-connection 生成器
- 早停策略：需要监控 loss 曲线，防止过拟合

**关键参数**：
- 迭代步数（默认 500~1000 步）
- 学习率
- 多帧模式（如用户上传多张短曝光图）

**性能预期**：
- 单图 DIP 2K：~ 2~5 min
- DIPLI 多帧（10 帧）：~ 10~20 min

**集成位置**：通道 B 的「精细恢复」模式，标注"慢但惊艳"，用户主动触发。

**开发工作量**：约 7~10 人天

## 四、GPU 服务器配置建议

### 4.1 最低配置（能跑，体验一般）

| 项目 | 规格 | 说明 |
|------|------|------|
| GPU | NVIDIA RTX 3060 12GB | 消费级，12GB 显存能跑大多数模型 |
| 显存 | 12 GB | 2K 图训练 N2V 刚好，4K 可能要切块 |
| CPU | 4 核以上 | 数据预处理、I/O |
| 内存 | 16 GB | 配合 GPU 处理大图 |
| 硬盘 | 200 GB SSD | 模型权重 + 临时文件 |

**适用场景**：开发测试、小流量验证
**预估费用**（云服务器）：约 3000~5000 元/月

### 4.2 推荐配置（生产可用）

| 项目 | 规格 | 说明 |
|------|------|------|
| GPU | NVIDIA RTX 4090 24GB / A10 24GB | 24GB 显存可处理 4K 大图 |
| 显存 | 24 GB | N2V 训练 + 超分 + DIP 都不费劲 |
| CPU | 8 核以上 | 并发处理数据 |
| 内存 | 32 GB | 大图像 + 多任务 |
| 硬盘 | 500 GB NVMe SSD | 模型 + 缓存 + 上传文件 |

**适用场景**：正式上线，支持 5~10 并发
**预估费用**（云服务器）：约 8000~15000 元/月

### 4.3 高性能配置（大规模）

| 项目 | 规格 | 说明 |
|------|------|------|
| GPU | NVIDIA A100 40GB / 80GB | 数据中心级，支持多任务 |
| 显存 | 40 GB+ | 批量处理 + 微调训练 |
| CPU | 16 核以上 | 高并发 |
| 内存 | 64 GB+ | - |
| 硬盘 | 1 TB+ NVMe SSD | - |

**适用场景**：产品化、用户量大
**预估费用**：约 2~4 万元/月

### 4.4 配置选型建议

- **初期验证**：选最低配置（3060 级别），把 4 个 AI 能力跑通，验证效果和用户反馈
- **正式运营**：升级到推荐配置（4090 / A10 24GB），保证 4K 大图流畅处理
- **为什么不选 8GB 显存卡**：8GB 跑 N2V 训练 2K 图很紧张，超分 ×4 基本装不下，性价比低

### 4.5 软件环境要求

- 操作系统：Linux（Ubuntu 20.04/22.04 或 CentOS 7/8）
- CUDA：11.8 或 12.x
- cuDNN：对应 CUDA 版本
- 深度学习框架：PyTorch 2.x（优先）或 TensorFlow
- Docker：需要 nvidia-docker2 运行 GPU 容器

## 五、架构设计要点

### 5.1 任务队列

AI 处理（尤其是 N2V 训练、DIP 优化）耗时长，不能同步阻塞 HTTP 请求。
建议引入任务队列（如 BullMQ / Celery），AI 任务入队，前端轮询或 WebSocket 推送进度。

### 5.2 GPU 资源调度

- 单 GPU 场景：串行处理，任务排队
- 多 GPU 场景：按 GPU 分配任务，每张卡同时跑 1 个训练任务或 2~4 个推理任务

### 5.3 模型权重管理

- 预训练模型权重（deepCR、Swin2SR）：服务启动时加载或首次调用时懒加载
- 权重文件放在独立目录，不打进 Docker 镜像（镜像太大）
- 启动时从对象存储或挂载卷读取

### 5.4 大图处理策略

- 超过 GPU 显存的图像：切块处理 + 拼接，注意边缘重叠避免接缝
- N2V 和超分都有成熟的 patch-based inference 方案

## 七、验收标准

每项 AI 能力上线需满足：

1. 功能完整：前端可选择、参数可调节、结果可下载
2. 性能达标：满足各能力的性能预期（2K 图场景）
3. 稳定性：连续 10 次处理成功率 100%
4. 效果评估：与通道 A 传统算法做 A/B 对比，有明显提升（主观评估 + 指标如 PSNR/SSIM）
